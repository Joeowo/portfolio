# ADR-0002: 采用 Nothing 设计系统

## 状态

已采纳 (2026-05-27)

## 上下文

Portfolio Platform 前端需要确立设计语言。

常见选项包括：
1. 使用组件库默认风格（如 Element Plus 默认）
2. 定制主题色（保留组件库结构，修改配色）
3. 完全自定义设计系统

## 决策

**采用 Nothing 设计系统（完整实施）**。

### Nothing 设计核心特征

| 特征 | 说明 |
|------|------|
| 单色调 | 颜色是事件，不是默认（除状态数据编码外） |
| 字体驱动 | 尺寸、字重、间距创造层级，不用颜色/图标/边框 |
| 减法哲学 | 每个元素必须证明其必要性，默认删除而非添加 |
| 精密系统感 | 4px 基数、小圆角（4-8px）、细边框、无阴影无渐变 |
| 机械而温暖 | 技术精确，但有人性温度 |
| 结构即装饰 | 暴露网格、数据、层次本身 |

### 实施范围

- **全部实施** Nothing 视觉特征（非简化版）
- 包括：点阵字体 hero、机械感控件、全大写标签、数据可视化
- 亮色模式优先（背景 `#F7F5F2`）
- 字体：Space Grotesk + Space Mono + Doto

### 技术实现

- CSS 变量管理设计 tokens
- SVG 纹理遮罩实现点阵文字效果
- 自研核心组件（卡片、列表、导航）
- 基础组件复用 Element Plus（按钮、输入框等），深度定制样式

## 理由

| 因素 | 说明 |
|------|------|
| 品牌差异化 | Nothing 风格鲜明，Demo 视觉冲击力强 |
| 设计完整性 | 统一的设计语言比混搭风格更专业 |
| 技术可行性 | CSS 变量 + Vue 组件可实现完整效果 |
| 展示价值 | 视觉原型型 Demo 需要强烈的设计表达 |

## 后果

### 正面

- 独特的视觉识别度
- 设计系统可复用
- 符合"精密系统感"定位

### 负面

- 开发工作量较大（自研组件、定制样式）
- 设计决策多，需要完整规范
- Element Plus 深度定制可能遇到兼容问题

### 缓解措施

- 分阶段实施：先建立 tokens，再开发组件
- 优先开发核心组件，边缘组件可简化
- 参考 Nothing 官方设计规范
