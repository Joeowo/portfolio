# ADR-0001: Demo 定位为视觉原型型

## 状态

已采纳 (2026-05-27)

## 上下文

Portfolio Platform 后端 API 已完整实现，前端需要开发一个 Demo 版本。

Demo 有三种典型定位：
1. **功能展示型** - 实现全部核心功能，但简化细节处理
2. **MVP 验证型** - 只实现最关键的功能路径
3. **视觉原型型** - 重点在 UI/UX 展示，数据可以是 Mock 的

## 决策

**选择视觉原型型定位**。

### 具体含义

- 优先级：视觉效果 > 交互完整 > 数据真实
- 可使用 MSW 模拟 API 响应，无需对接真实后端
- 核心目标：展示 6 个模块的完整界面和设计语言
- 非核心功能（如版本回滚、AI 翻译）可做简化处理

### 实施范围

- 包含全部 6 个模块的 UI（认证、素材库、作品编辑器、模版选择、网页管理、管理后台）
- 覆盖主要交互流程（登录→上传素材→创建作品→生成网页）
- 数据可使用 Mock，但交互要真实（加载状态、错误处理、验证反馈）

## 理由

| 因素 | 说明 |
|------|------|
| 展示需求 | Demo 通常需要给干系人（投资人/客户/团队）看完整产品能力 |
| 设计系统验证 | 前端的核心价值是确立 Nothing 设计系统的视觉规范 |
| 开发效率 | 视觉原型可快速迭代，不需要等待后端联调 |
| 后续迁移 | 使用 MSW 模拟真实 API，后续对接时只需切换 base URL |

## 后果

### 正面

- 可快速展示完整产品能力
- 设计系统可独立验证和迭代
- 降低开发复杂度，聚焦视觉

### 负面

- 非真实数据，可能隐藏实际使用问题
- 后续对接真实 API 需要额外工作
- 某些边缘交互可能未覆盖

### 缓解措施

- Mock 数据结构与真实 API 保持一致
- 保留 API 调用的接口抽象，便于切换
- 核心交互路径尽量完整
